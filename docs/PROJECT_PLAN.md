# TalkFrog — мастер-план проекта

Кроссплатформенное приложение (Web, iOS, Android) для обучения английскому с нуля по методике Эли и Влада.

## 1. Техническая архитектура

### 1.1 Клиент

| Слой | Технология |
|------|------------|
| UI | React Native + Expo SDK + TypeScript |
| Навигация | Expo Router (file-based) |
| Web | react-native-web, react-dom, @expo/metro-runtime |
| Стили | Централизованная тема `src/theme/theme.ts` |

### 1.2 Бэкенд (Supabase)

- **Auth:** гость (лимиты), email, Google, Apple, Telegram (по мере подключения провайдеров).
- **PostgreSQL:** профили, прогресс уроков, покупки, админ-учётки.
- **Edge Functions:** промпты Gemini 3.8, оценка ответов, прокси без утечки ключей.
- **RLS:** пользователь видит только свои данные; админ — отдельные политики.

### 1.3 Ключевые таблицы (черновик)

- `profiles` — карточка пользователя после онбординга.
- `lesson_progress` — статус усвоения, оценка ИИ, цвет «листа».
- `purchases` / `subscriptions` — синхронизация с StoreKit / Google Play Billing.
- `admin_users` — логин/хеш пароля, PIN (хранить хеш, не plaintext).

### 1.4 Сервисы на клиенте

| Сервис | Назначение |
|--------|------------|
| `AuthService` | Сессия Supabase, гость, OAuth |
| `PermissionsService` | Микрофон и будущие разрешения (единая точка) |
| `BillingService` | Apple StoreKit + Google Play Billing → Supabase |
| `PronunciationService` | Левенштейн + порог % (локально или с серверной валидацией) |
| `AiTutorService` | Вызов Edge Functions, без ключей в приложении |

## 2. Пользовательские потоки

### 2.1 Онбординг

1. Экран **пользовательского соглашения** и **согласия на обработку голоса** (отдельные чекбоксы / явное принятие).
2. Выбор входа: **Гость** (лимиты) | Email | Google | Apple ID | Telegram.
3. Создание записи в `profiles` (имя, аватар опционально, `auth_user_id`, флаги согласий).
4. `PermissionsService`: запрос микрофона с понятным русским объяснением (связь с `NSMicrophoneUsageDescription` / Android permissions).

### 2.2 Главный экран (Home)

- **Шапка:** слева PNG-логотип + «TalkFrog»; **5 тапов по логотипу** → скрытая админка; справа — кнопка модального **короткого видео** от преподавателя.
- **Инфо-блок** на всю ширину.
- **Зона ярких объявлений** (контрастные баннеры).
- **Hero-кнопка** «Нулевой уровень» (главный акцент).
- **Сетка 2×3:** «1 курс» … «6 курс».

### 2.3 Экран «Нулевой уровень»

- Верх: в ряд **«Прочти меня»** (слева) | **«Тарифные планы»** (справа).
- Скролл: кнопки-**листья кувшинки** в шахматном порядке (2 колонки, вертикальный сдвиг, узкие части навстречу).
- Полупрозрачный **водяной знак лягушонка** под текстом урока.
- Цвет листа — от **оценки усвоения ИИ** (см. тему: mastery colors).
- Уроки 1–8: `ABC`, `123`, `Hello?`, `My name.`, `I & U`, `Thanks`, `I'm OK`, `I'm 20`.

### 2.4 Урок (будущие шаги)

- Воспроизведение / запись голоса, отправка на Edge Function, обновление `lesson_progress`, смена цвета листа.

## 3. Монетизация

- Абстракция `BillingService`:
  - iOS: StoreKit 2 (или актуальный API Expo/React Native на момент реализации).
  - Android: Google Play Billing.
- После покупки: верификация (по возможности server-side) и запись в Supabase.
- **Восстановление покупок** — обязательная кнопка в настройках/тарифах.

---

## 4. Скрытая админ-панель (Эли и Влад)

1. 5 тапов по логотипу на главном экране.
2. Первый вход: **логин + пароль** из Supabase (`admin_users`), поля с **показать/скрыть** для логина и пароля.
3. Создание **4-значного PIN** (хранить хеш).
4. Последующие входы — только PIN (с возможностью сброса через пароль по политике безопасности).

Функции админки (позже): объявления, видео-приветствие, тарифы, модерация контента.

---

## 5. ИИ-преподаватель

- Промпты и вызов Gemini 3.8 — **только Edge Functions**.
- Вход: текст/транскрипт речи пользователя, контекст урока, языковые требования C1–C2 для эталонных фраз.
- Выход: оценка усвоения, feedback на русском, рекомендация следующего шага.

---

## 6. Оценка произношения

- Нормализация строк (регистр, пунктуация по правилам).
- Расстояние Левенштейна → процент совпадения.
- Порог по умолчанию в конфиге (env / remote config), переопределение для детских уроков при необходимости.
